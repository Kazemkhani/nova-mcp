# Security policy

## Supported versions

Security fixes are applied to the latest released `1.x` version. Please upgrade before reporting a problem that is already fixed in a newer release.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability. Email [amir@amirkazemkhani.com](mailto:amir@amirkazemkhani.com) with:

- the affected version and environment;
- a minimal reproduction or proof of concept;
- the expected impact;
- any suggested mitigation; and
- whether the issue has been disclosed elsewhere.

You should receive an acknowledgement within three business days. Please allow time for investigation and a coordinated fix before public disclosure.

## Sensitive data

Never include NOVA API keys, bearer tokens, phone numbers, call recordings, transcripts, webhook secrets, or customer data in a report. Use clearly fake values and redact logs.

Good-faith research that avoids privacy violations, data destruction, service disruption, and access to other users' data is welcome.
